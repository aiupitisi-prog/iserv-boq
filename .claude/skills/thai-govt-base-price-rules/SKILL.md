# หลักเกณฑ์ราคากลางงานก่อสร้าง (ภาครัฐ) — เช็กลิสต์

> ⚠️ **กฎเหล็กของเอกสารนี้:** ตัวเลขทั้งหมด (ตาราง Factor F, อัตราค่าแรง 30–37%, อัตราเงินเผื่อจำเป็น,
> อัตราดอกเบี้ย) ต้องมาจาก**เอกสารทางการที่มีผลบังคับ** (ราชกิจจานุเบกษา — หลักเกณฑ์การคำนวณราคากลางงานก่อสร้าง
> ฯลฯ) โดยเก็บใน ruleset registry พร้อม `sourceDoc`, `effectiveFrom`, `checksum`
> **ห้าม copy ตัวเลขจากความจำหรือจากสรุปที่ไม่เป็นทางการ** — ถ้าไม่มีเอกสารต้นฉบับในมือ ให้ตอบ
> **"unverified"** และระบุว่าต้องเปิดเอกสารใดมาตรวจ ห้ามเดาข้อกฎหมาย

## โครงสร้างการคำนวณ (ลำดับบังคับ)

1. รายการ: ราคาวัสดุ/ค่าแรงต้นทุนจริง → รวมเงินต่อรายการ (ปริมาณ × ราคาต่อหน่วย)
2. รวมต่อแบบ **ปร.1** (งานก่อสร้าง) → "ต้นทุนโดยตรงของโครงการ" (A)
3. **Factor F** — ปรับปรุงราคากลางตามเงื่อนไขการจ่ายเงิน (เงินรับล่วงหน้า / เงินประกันผลงาน / อัตราดอกเบี้ย / VAT):
   - เลือกตารางจาก (advancePct, retentionPct, interestPct, vatPct)
   - หาแถวช่วง [B, C] ที่ A อยู่ระหว่าง → **F = D − (D − E) × (A − B) / (C − B)**
   - A เท่ากับขอบตารางพอดี (B หรือ C) → ใช้ค่าแถวนั้นตรง ๆ ไม่ interpolate
   - A อยู่นอกตาราง → **throw typed error — ห้าม extrapolate**
   - **ห้ามคำนวณ F จากองค์ประกอบเอง** — ตารางมาจาก ruleset registry เท่านั้น
4. **ปร.1(ก)**: สรุปราคากลาง × Factor F (แสดง trace การคำนวณได้)
5. **ปร.2(ก)**: งานจัดซื้อครุภัณฑ์ — **แยกจากงานก่อสร้าง** + คิด VAT เป็นบรรทัดแยก
6. **ปร.3, ปร.4**: สรุปรวม / เงินเผื่อจำเป็น ตามแบบฟอร์มราชการ
7. **ค่าแรง fallback 30–37%**: เมื่อแยกค่าแรงออกจากต้นฉบับไม่ได้ — ต้องมีเหตุผลเขียนกำกับทุกครั้ง

## กฎเหล็ก

- **แยกโหมดให้ชัด**: โหมดราชการห้ามเปิดปัจจัย % อิสระ (กำไร/โอเวอร์เฮด/S.W.C./เงินเผื่อแบบเอกชน) —
  โหมดเอกชนห้ามใช้คำ "ราคากลาง" โดยไม่ติดป้าย **"ประมาณการ — ไม่ใช่ราคากลางตามหลักเกณฑ์"**
- **ครุภัณฑ์จัดซื้อ** (part = "equipment") **ห้ามเข้าฐานคำนวณ Factor F**; ค่าติดตั้งเป็นบรรทัดแยก + มีเหตุผลเขียนไว้
- **ตัวเงิน**: ใช้สตางค์ integer (หรือ decimal library) — **ห้ามใช้ float**; เก็บทศนิยมเป็น string ใน JSON;
  ปัดเศษเฉพาะจุดที่ ruleset กำหนดเท่านั้น — ถ้า ruleset เงียบ ให้คืนค่าไม่ปัด + บันทึก open question ใน trace
- **ทุกแถวที่มีราคาต้องมี PriceEvidence**; แหล่งราคาอื่นนอกจาก TPSO/ตารางค่าแรง ต้องมีเหตุผลกำกับ;
  ราคาเกิน 12 เดือน หรือมาจากเดือนที่ สนค. ยกเลิกเผยแพร่ → flag เตือน (ดู skill `tpso-price-integration`)
- **เอกสารพิมพ์ "ชุดสมบูรณ์"** ต้องครบ 9 เอกสาร พร้อมช่องลงนามผู้จัดทำ / ผู้ตรวจสอบ / ผู้อนุมัติ
- Ruleset ที่ถูกประกาศใหม่แทนที่ → ตั้ง `supersededBy` + ใส่ `warn` notice; โปรเจกต์ pin `rulesetId`;
  เปิดโปรเจกต์ที่ใช้ ruleset เก่า → เตือนผู้ใช้

## เวกเตอร์ทดสอบมาตรฐาน (ตรวจยืนยันกับเอกสารต้นฉบับก่อนใช้งานจริง)

| เคส | ค่า | คาดหวัง |
|---|---|---|
| Interpolate | B=10, C=20, D=1.2500, E=1.2000, A=15 | **F = 1.2250** |
| Mixed funding | 0.6×1.1038 + 0.4×1.1810 | **1.13468** (เอกสารแสดง 1.1346 — บันทึกหมายเหตุการปัดเศษ) |
| ขอบตาราง | A = B และ A = C | ได้ค่าแถวนั้นตรง ๆ ไม่ interpolate |
| นอกตาราง | A นอกช่วง | typed error — ห้าม extrapolate |
| เพิ่มครุภัณฑ์ | บวกรายการ equipment | F คงเดิม |
| ย้ายแถว | ย้ายรายการระหว่างกลุ่มของ part เดียวกัน / สลับลำดับ | ราคารวมไม่เปลี่ยน |

## แนวทาง implement (lib/calc — เฟส 2–3 ของ PRD)

- Pure functions เท่านั้น: `compute(project, ruleset) → Result` พร้อม **trace ทุกขั้น**
  (input, สูตร, ค่าระหว่างทาง, rulesetId) — trace ต้องแสดงในรายละเอียด ปร.1(ก) ได้
- Vitest: ไฟล์ละฟอร์ม (pr1, pr1a, pr2a, pr3, pr4) + `factorF.test.ts` + property tests
- ทุกข้อสมมติที่ยืนยันจากเอกสารไม่ได้ → ระบุไว้ให้มนุษย์ไปตรวจกับราชกิจจานุเบกษาต้นฉบับ
