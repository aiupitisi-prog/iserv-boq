## 1. บทสรุป (Executive Summary)

iServ BOQ เป็นเว็บแอปพลิเคชันสำหรับ**จัดทำใบประมาณราคา (BOQ) งานก่อสร้าง**ของหน่วยงาน
และผู้รับเหมา โดยเน้น 3 จุดขายหลัก:

1. **จัดทำ BOQ ได้ทันที** — กรอกตาราง ระบบคำนวณเงินต่อรายการและต่อหมวดให้อัตโนมัติ
   พิมพ์เอกสารเป็น A4 เพื่อประมวลผล/ประเมินราคาได้
2. **คลังราคาวัสดุก่อสร้างจริง** — ดึงราคาที่สำนักงานนโยบายและแผนการขนส่ง (สนค./TPSO)
   เผยแพร่ แยกตามจังหวัด/ปี/หมวดวัสดุ 21 หมวด รายการกว่า 6,400 รายการ
3. **ข้อมูลเป็นของผู้ใช้** — โครงการเก็บในเบราว์เซอร์ของผู้ใช้ (localStorage)
   ส่งออก/นำเข้า JSON ได้ ไม่มีเซิร์ฟเวอร์เก็บข้อมูลโครงการ

เอกสารฉบับนี้ประกอบด้วย (ก) รายงานสิ่งที่พัฒนาเสร็จแล้วทั้งหมด (ข) ข้อจำกัดและความเสี่ยง
(ค) แผนพัฒนาแบ่งเป็น 6 เฟส พร้อมเกณฑ์ตรวจรับ (ง) ภาคผนวกเทคนิค (TPSO API, data model)
เพื่อใช้เป็นแนวทางพัฒนาต่อให้ทีม/ผู้ร่วมพัฒนารายใหม่เข้าใจตรงกัน

### 2.5 Data Model ปัจจุบัน

```ts
// lib/boq.ts (สถานะจริง พ.ย. 2569)
type BoqType  = "ปร.1" | "ปร.2" | "ปร.3" | "ปร.4"
type ProjectMode = "gov" | "private"                                  // โปรเจกต์เก่า = "gov"
type ProjectFactors = { contingencyPct?; profitPct?; swcPct?; vatPct? } // โหมด private เท่านั้น
type PriceSource   = { kind: "tpso"; code; prov; provName; year; month; priceAtPick; pickedAt }
                     | { kind: "private"; entryId; category; note?; priceAgeRef; priceAtPick; pickedAt }
type BoqItem  = { id; section; name; unit; qty; price;                // price = บาท/หน่วย
                  source?; note?;
                  part?: "construction" | "equipment";                // ครุภัณฑ์แยกฐาน Factor F
                  matPrice?; laborPrice? }                            // แยกค่าวัสดุ/ค่าแรงต่อหน่วย
type ProjectAward = { winningPrice?; contractNoteDate?; contractor?; contractorSigner?; savedAt? }
type BoqProject = { id; name; address; boqType; createdAt; items;
                    province?; budgetYear?; mode?; factors?; rulesetId?; award? }

// lib/ruleset.ts (F2.4) — เรจิสทรีตัวเลขกฎหมาย (มีชุดตาราง Factor F ว 481 แล้ว — commit 1629c5ec)
type FactorFTable = { advancePct; retentionPct; interestPct; vatPct;
                      workType?: "building" | "road" | "bridge" | "irrigation";  // ว 481 = 4 ประเภทงาน × 12 ตาราง
                      rows: { B; C; D; E; F?; G?; D2?; E2?; D3?; E3?; anomalyNote?; open? }[] }
type Ruleset = { id; name; sourceDoc; sourceUrl?; effectiveFrom; checksum;
                 factorF?; factorFTables?; labor?; contingencyPct?; swcPct?; durableHandlingPct?;
                 notices?; supersededBy?; createdAt }

// lib/tpso.ts — ราคาจาก สนค. (แปลงแล้ว)
type TpsoItem = { code; name; unit; headCategory; headCategoryName;
                  price; priceVAT; month; year }                      // price = ราคาล่าสุดของปีที่เลือก
```

> **ช่องว่างเชิงโครงสร้างตามระเบียบ 2569** — โดยย่อ (ดูละเอียดส่วนที่ 5.4):
> `boqType` (แบบเดียวต่อโปรเจกต์) ไม่ครอบคลุมชุดเอกสารรายงาน 9 ชิ้นตามข้อ 11 (ปร.1 หลายชุด/งาน + ปร.1(ก) ต่อกลุ่มงาน + ปร.2/ปร.2(ก)/ปร.3/ปร.4 ฯลฯ);
> `BoqItem` ต้องเก็บ **ค่าติดตั้ง** แยกจากค่าครุภัณฑ์ (ราคาผู้ผลิต/จำหน่ายไม่รวม VAT) และราคาต้นทุนต้องระบุว่า "ยังไม่รวมค่าอำนวยการ/ดอกเบี้ย/กำไร/VAT" — ทุกฟิลด์ใหม่ต้องเป็น optional เพื่อคง backward compatibility กับโปรเจกต์เก่า

### 5.2 โครงการคำนวณราคากลางใหม่ (งานก่อสร้างอาคาร — เล่ม 2)

**สูตรหลัก (อ่านจากหน้า 174–177 และแบบฟอร์ม ปร.4):**

```
ค่าก่อสร้าง (ต่องาน/กลุ่มงาน) = ค่างานต้นทุน × Factor F (เทียบจากตาราง)
ราคากลางทั้งโครงการ = Σค่าก่อสร้างทุกกลุ่มงาน
                    + ค่าครุภัณฑ์จัดซื้อ (= ราคาผู้ผลิต/จำหน่าย ไม่รวม VAT + ค่า VAT อัตราปัจจุบัน + ค่าติดตั้งที่สืบราคา)
                    + ค่าใช้จ่ายพิเศษตามข้อกำหนด (ถ้ามี — รายการที่ต้องชำระ VAT ให้รวม VAT ด้วย)
```

- **โครง "ส่วน ก. ค่าวัสดุอย่างน้อยที่สุด / ส่วน ข. ค่าแรง / ส่วน ค. เงินเผื่อจำเป็น / ส่วน ง. ค่าดำเนินงาน (S.W.C.)" ไม่ปรากฏในการคำนวณตามแบบฟอร์มเล่ม 2 อีกต่อไป** — แทนด้วยกลุ่มรายการ 3 กลุ่ม: ค่างานต้นทุน (แบบ ปร.1 — รวมค่าวัสดุและค่าแรง), ค่าครุภัณฑ์จัดซื้อ (แบบ ปร.2 → ปร.2(ก)), ค่าใช้จ่ายพิเศษตามข้อกำหนด (แบบ ปร.3) โดยค่าอำนวยการ/ค่าดอกเบี้ย/ค่ากำไร/VAT แฝงใน Factor F · **"เงินเผื่อจำเป็น" ไม่ปรากฏในโครงการคำนวณของเล่ม 2** (คำ "เงินเผื่อ" ไม่พบทั้งเล่ม 1 และเล่ม 2 — คำที่พบคือ "การเผื่อ" ซึ่งหมายถึงการเผื่อเพิ่มวัสดุต่อหน่วยงานตอนถอดแบบ ไม่ใช่ส่วนเพิ่มในราคากลาง)
- ลำดับการคำนวณ 12 ขั้น (สรุปข้อ 1–12 เล่ม 2): ถอดแบบ → คำนวณรายการ 3 กลุ่ม (ต้นทุน "ยังไม่รวมค่าอำนวยการ/ค่าดอกเบี้ย/ค่ากำไร/VAT" · ครุภัณฑ์ราคาผู้ผลิต/จำหน่าย ไม่รวม VAT + แยกสืบค่าติดตั้ง · ค่าใช้จ่ายพิเศษตามข้อกำหนด ตามบัญชีตัวอย่าง 15+ รายการ) → รวมขึ้น ปร.1 / ปร.2(ก) → รวมค่างานต้นทุนทั้งโครงการ → เทียบหา Factor F → "ค่างานต้นทุน × F = ค่าก่อสร้าง" ใน ปร.1(ก) → ยกผลสรุปไว้ ปร.4 (+ตัวอักษร) → จัดรายงาน 9 ชิ้น (ตามข้อ 11) → เสนอหัวหน้าหน่วยงานผ่านหัวหน้าเจ้าหน้าที่ให้ความเห็นชอบ (ข้อ 12)
- ข้อกำหนดการสืบราคาครุภัณฑ์: ต้องแยกราคาครุภัณฑ์ออกจากค่าติดตั้ง — ราคาครุภัณฑ์ห้ามแฝงส่วนติดตั้ง พร้อมแสดงเหตุผลความจำเป็นการติดตั้งไว้ในเอกสาร

### 5.3 กลไก Factor F (เล่ม 2 ข้อ 9 หน้า 174–181 + เงื่อนไขการใช้ + ว 481)

- ค่าใช้จ่ายในการดำเนินงานก่อสร้าง (Indirect Cost) รวมเป็นตัวเดียวเรียก **ค่า Factor F** — จำแนก 4 หมวดใหญ่: **หมวดค่าอำนวยการ · ค่าดอกเบี้ย · ค่ากำไร · ค่าภาษีมูลค่าเพิ่ม**; หมวดค่าอำนวยการมี 4 หมวดย่อย (1.1 ขั้นตอนการทำสัญญา — ค่าธรรมเนียมค้ำประกันสัญญาจ้าง/ค้ำประกันผลงาน 2 ปี/อากรแสตมป์ติดสัญญา/สมทบกองทุนเงินทดแทน+ประกันสังคม · 1.2 สำนักงาน ที่พักคนงาน และโรงงาน · 1.3 บริหารโครงการและบุคลากร — PM/สถาปนิก-วศ.ประจำ/โฟร์แมน/จป. ฯลฯ · 1.4 บริหารความเสี่ยง — เบี้ยประกันภัยและความเสี่ยงอื่น)
- **ตาราง Factor F งานอาคารมี 12 ตาราง** — ผันตาม (อัตราเงินค่าจ้างล่วงหน้า × อัตราเงินประกันผลงาน) ที่กำหนดในสัญญา; ผู้คำนวณต้องเลือกตารางให้ตรงเงื่อนไข และบันทึกทั้ง 4 อัตราลงกล่อง "เงื่อนไขการใช้ตาราง Factor F" ในแบบ ปร.1(ก) ด้วย — ประกาศ ว 481 ต่อยอดเป็น **4 ประเภทงาน × 12 = 48 ตาราง** (อาคาร/งานทาง/สะพาน+ท่อเหลี่ยม/ชลประทาน) ต้องเพิ่มฟิลด์ `workType` ใน FactorFTable (optional, backward-compat)
- องค์ประกอบช่องของแต่ละตาราง: ช่วงค่างานต้นทุน (ล้านบาท) · ค่าอำนวยการ · ค่าดอกเบี้ย · ค่ากำไร · รวมค่าใช้จ่าย (= อำนวยการ + ดอกเบี้ย + กำไร) · **"รวมในรูป Factor" (ยังไม่รวม VAT)** · ค่าภาษีมูลค่าเพิ่ม · **Factor F (รวม VAT แล้ว)** — เก็บเทียบหน้าตารางต้นฉบับทุกช่อง อย่าลดรูปเหลือแค่ FactorFRow เดิม (ขยายโครง FactorFTable ด้วยฟิลด์ optional แบบ backward-compatible)
- สูตรดอกเบี้ยรวมโครงการ: `I = i/12 × [ r/100 + (T+D−1)·a/100 − (a+r)/100 · (T+1)/2 − (D−1) ]` (T = ระยะเวลาเดือน; D = ช่วงเวลาการรับเงิน; a = อัตราเงินค่าจ้างล่วงหน้า %; i = อัตราดอกเบี้ยเงินกู้ต่อปี %; r = อัตราเงินประกันผลงาน %) — อัตรา i ให้ใช้ค่าเฉลี่ย MLR ของธนาคารขนาดใหญ่อย่างน้อย 3 ธนาคาร กำหนดเป็นตัวเลขกลม (ถ้าเศษถึง 0.50 ปัดขึ้น ไม่ถึง 0.50 ปัดลง) โดยกรมบัญชีกลางเป็นผู้กำหนดและประกาศ → ปัจจุบัน **6%** (ประกาศ ว 481); ถ้าอัตราดอกเบี้ยเงินกู้เฉลี่ยเปลี่ยนแปลงถึงร้อยละ 1 กรมบัญชีกลางจัดทำและแจ้งเวียนตาราง Factor F ชุดใหม่ → ระบบต้อง import เป็น ruleset ใหม่ + ตั้ง `supersededBy` ให้ ruleset เดิมและเตือนโปรเจกต์ที่ pin อยู่ (เทียบเล่ม 2 ข้อ 9.2 หมวดค่าดอกเบี้ย — อ่านจากสแกน ตรวจซ้ำกับต้นฉบับ)
- หมวดค่ากำไร: กำหนดให้ใช้อัตรากำไรทางธุรกิจ (Financial Profit) หรือกำไรเชิงธุรกิจ (Excess Profit) ที่สูงกว่าอัตราดอกเบี้ยเงินฝากประจำ ในอัตราร้อยละ **3.5–5.5 ของค่างาน (ทุน)** — ระบบไม่ต้องมีช่องตั้งกำไร ให้ใช้ค่าที่ฝังในตาราง Factor F โดยตรง
- สูตรเทียบอัตราส่วนระหว่างช่วง (9.3 ข้อ 2): `F ของค่างานต้นทุน A = D − (D−E)·(A−B)/(C−B)` โดย B/C = ขอบล่าง-บนของช่วงต้นทุน — โครงนี้ตรงพอดีกับ FactorFRow {B, C, D, E} ที่ lib/ruleset.ts มีอยู่แล้ว
- ค่า Factor F ใช้ทศนิยม 4 ตำแหน่ง (ตัวอย่างเล่ม 2 หน้า 181: ค่างานต้นทุน 400 ล้านบาท กำหนด a=10%, r=5%, i=7%, VAT=7% → ช่อง "รวมในรูป Factor" = 1.1038, ช่อง "Factor F" = 1.1810; โครงการเงินกู้ JBIC 60% + งบประมาณสมทบ 40% → Factor F ที่ใช้ = 1.1038×0.6 + 1.1810×0.4 = 0.6622 + 0.4724 = **1.1346**) — ตารางว 481 (ดอกเบี้ย 6%) ใช้เป็นเวกเตอร์ตรวจทุกจุดก่อนแตะโค้ด
- เงื่อนไขการใช้ตาราง (9.3) สาระที่เครื่องยนต์ต้องบังคับ: งานอาคารเท่านั้น · สัญญาเดียวให้รวมค่างานต้นทุนทั้งสัญญาเพื่อเทียบ F · เงินกู้แหล่งไม่ต้องชำระ VAT 100% ให้ใช้ช่อง "รวมในรูป Factor" · กรณีเงินกู้+งบ สมทบ ให้คิดถ่วงน้ำหนักตามสัดส่วนเงินทุน · ตารางจะไม่รวมเงื่อนไขฝนตกชุก (แตกต่างจากงานทาง) · ใช้ได้กับค่าน้ำมันเชื้อเพลิงทุกราคา · ตารางผันตามอัตรา 4 ตัวใน ปร.1(ก)
- อัตราภาษีมูลค่าเพิ่ม (VAT) ให้กำหนดเป็นตัวเลขกลมด้วยวิธีเดียวกับดอกเบี้ย (ถ้าเศษถึง 0.50 ปัดขึ้น ไม่ถึง 0.50 ปัดลง — ประกาศหลักข้อ 14) · เมื่อมีพระราชกฤษฎีกาเปลี่ยนอัตรา VAT กรมบัญชีกลางจะประกาศเปลี่ยนแปลงพร้อมจัดทำและแจ้งเวียนตาราง Factor F ใหม่ → ใช้กลไก import ruleset + `supersededBy` เดียวกับกรณีดอกเบี้ยเปลี่ยน
- ข้อ 19 (ทบทวนเมื่ออัตราเปลี่ยน): ได้รับแจ้งเปลี่ยนอัตราดอกเบี้ยเงินกู้/VAT/ตารางค่าขนส่ง/ตารางค่าเสื่อมราคาเครื่องจักร/บัญชีค่าแรงงาน ฯลฯ ก่อนประกาศสอบราคา/ประกวดราคา/เชิญชวน → ต้องคำนวณราคากลางใหม่และถือราคาใหม่ · ได้รับแจ้งภายหลังการประกาศแล้ว → ดำเนินการต่อด้วยราคาเดิม ไม่ต้องคำนวณใหม่ · เผยแพร่ประกาศบนเว็บกรมบัญชีกลางแล้วถือว่าได้รับแจ้ง (ข้อ 19.1–19.3 + หมายเหตุ 2 — อ่านจากสแกน)
- ข้อ 20–21 (เปิดเผย + ระบบอิเล็กทรอนิกส์): ให้ประกาศเปิดเผยราคากลางพร้อมแนบรายละเอียดการคำนวณตามแบบแสดงรายการ ปริมาณงาน และราคา (BOQ) ทางเว็บไซต์ของหน่วยงานและของกรมบัญชีกลาง — งานอาคารใช้แบบ ปร.1 · ปร.1(ก) · ปร.2 · ปร.2(ก) · ปร.3 · ปร.4 (งานทาง-สะพาน-ท่อเหลี่ยม และงานชลประทานใช้แบบฟอร์มสรุปราคากลาง) · ข้อ 21 การคำนวณด้วยอิเล็กทรอนิกส์ต้องเป็นไปตามหลักเกณฑ์ แนวทาง และวิธีการที่กรมบัญชีกลางกำหนด → ระบบต้อง export ชุด BOQ สำหรับเผยแพร่ทางเว็บได้ทันที และเฝ้าตามประกาศวิธีการคำนวณอิเล็กทรอนิกส์ของกรมบัญชีกลางอยู่เสมอ (อ่านจากสแกน)

## 6. แผนพัฒนาแบ่งเฟส (Roadmap)

> ประมาณการเป็น "วันทำงาน" ของผู้พัฒนา (ใช้ AI ช่วยเขียนได้) แต่ละเฟส deploy จบ
> และใช้งานได้จริงแยกกัน (ไม่ต้องรอเฟสถัดไป) เรียงตามความคุ้มค่าต่อแรงงาน

### เฟส 1 — เชื่อมคลังราคา → BOQ editor ⭐ (ทำต่อทันที)

**เป้าหมาย:** ผู้ใช้เพิ่มรายการ BOQ โดยเลือกจากคลังราคา สนค. แทนพิมพ์เอง ลดเวลาและพลาดน้อยลง

| ฟังก์ชัน | รายละเอียด |
|---|---|
| F1.1 ตั้งค่าอ้างอิงระดับโปรเจกต์ | เพิ่มฟิลด์ `province` (จังหวัด) และ `budgetYear` (ปีงบ พ.ศ.) ใน `BoqProject` — ใช้เป็นค่าเริ่มต้นเมื่อเลือกราคา |

**เป้าหมาย:** รองรับรายการที่ไม่มีใน สนค. (ค่าแรง, อุปกรณ์, วัสดุท้องถิ่น) และคิดราคาส่งมอบงาน

- F2.1 **รายการราคาส่วนตัว** — CRUD คลังราคาในเครื่อง (เก็บ localStorage), ใช้ปนกับราคา สนค. ใน modal ของเฟส 1 ได้, import/export JSON
- F2.2 **ปัจจัยราคาระดับโปรเจกต์** — ตั้ง % ได้แก่ กำไร+โอเวอร์เฮด, ค่าดำเนินงาน (S.W.C.), เงินเผื่อจำเป็น, VAT 7% → แสดงสรุปก่อนราคารวมท้ายตาราง (แยกชัดเจนว่า "ราคาวัสดุ-แรงงาน" กับ "ราคาเสนอ")
- F2.3 **คัดลอกโปรเจกต์/รายการ** — ทำซ้ำ BOQ ปีก่อนมาแก้
- F2.4 **Ruleset registry (เตรียมเครื่องยนต์ราคากลาง)** — เก็บตาราง/อัตราที่ใช้คำนวณ (ตาราง Factor F, ตารางค่าแรง, เงินเผื่อ) จาก**เอกสารทางการเท่านั้น** พร้อม `sourceDoc / effectiveFrom / checksum / notices`; ประกาศใหม่ทับตารางเดิม → `supersededBy` + warn — ห้าม hardcode ตัวเลขกฎหมาย (รายละเอียดใน skill `thai-govt-base-price-rules`)

**เกณฑ์ตรวจรับ:** เพิ่มรายการค่าแรงจากคลังส่วนตัวได้; สรุปท้ายตารางแสดงทุกปัจจัยถูกลำดับการคิดตามหลักประมาณราคา; export JSON รอบรวมข้อมูลใหม่

**ประมาณการ:** 2–3 วัน

> **สถานะเฟส 2 (พ.ศ. 2569):** ตรวจรับผ่านทั้งหมด — ส่งมอบเพิ่มจากสเปก: แยกโหมดโปรเจกต์ `gov | private` (โหมดเอกชนติดป้าย "ประมาณการ — ไม่ใช่ราคากลางตามหลักเกณฑ์" ทุกจุด, โหมดราชการไม่มีปัจจัย % อิสระ), PriceEvidence รองรับ 2 ชนิด (`tpso | private`), หน้า `/my-prices` CRUD + import/export, และ `lib/ruleset.ts` (registry เริ่มต้นว่าง — ตัวเลขกฎหมายจะ import จากเอกสารจริงในเฟส 3) — compliance review ผ่านทุกข้อ

### เฟส 3 — BOQ ขั้นสูง + เอกสารราชการตรงระเบียบ 2569

**เป้าหมาย:** เอกสารพิมพ์ออกมาตรงแบบฟอร์มที่หน่วยงานใช้จริง *(ปรับเป้าหมายใน v1.2: ทำตาม GAP ส่วนที่ 5.4 — ชุดรายงานตามข้อ 11 เล่ม 2 จำนวน 9 ชิ้น แทนโครง ส่วน ก./ข./ค./ง. เดิม; และตามข้อ 20 ได้ชุด BOQ สำหรับเผยแพร่ทางเว็บด้วย)*

- F3.1 จัดลำดับรายการ (ย้ายขึ้น/ลง, ลากสลับ), จับกลุ่มตามหมวดแบบยุบ/ขยาย
- F3.2 เลขหน้า/หัว-ท้ายกระดาษ, ลงชื่อผู้จัดทำ/ผู้ตรวจสอบ, ตัวเลขเงินเป็นตัวหนังสือ ("บาทถ้วน")
- F3.3 รูปแบบการพิมพ์: รายงานตามระเบียบ 2569 (แบบ ปร.1 + ปร.1(ก) เป็นค่าเริ่มต้น — พิมพ์ทั้งชุดหรือเฉพาะฉบับ), ใบเสนอราคาเอกชน (โหมด private)
- F3.4 ส่งออก **Excel (xlsx)/CSV** นอกจาก JSON
- F3.5 **เครื่องยนต์คำนวณราคากลาง `lib/calc/`** — pure functions `compute(project, ruleset) → Result` พร้อม trace ทุกขั้น; Factor F lookup + interpolation; ครุภัณฑ์แยกจากฐาน Factor F; ตัวเงินเป็นสตางค์ integer ห้าม float — สูตร กฎ และเวกเตอร์ทดสอบมาตรฐานอยู่ใน skill `thai-govt-base-price-rules` (ใช้ agent `boq-calc-engineer`)
- F3.6 **เอกสารพิมพ์ชุด 9 ฉบับตามข้อ 11 เล่ม 2** (ปร.1(ก) · ปร.1 · ปร.2(ก) · ปร.2 · ปร.3 ถ้ามี · แบบแสดงการคำนวณและเหตุผลความจำเป็นของค่าใช้จ่ายพิเศษ · ปร.4 · รายละเอียดการหาค่า Factor F · แบบบันทึกแสดงเหตุผลการสืบและการกำหนดราคาวัสดุ) — ✅ **ทำแล้ว (ปิด GAP G2 ส่วนที่ 5.4 — รวมช่องลงนาม ประธาน/กรรมการ×2)** · ✅ **export ชุด BOQ สำหรับเผยแพร่ตามข้อ 20 ทำแล้ว (13 พ.ย. 2569)** — xlsx หลายชีตจาก `lib/export-reg2569.ts` ผ่านปุ่มดาวน์โหลดที่หน้าชุดเอกสาร · ⏳ ที่เหลือ: การแก้ต่อฉบับเพิ่มเติมจากฟีดแบ็กหน่วยงาน

**เกณฑ์ตรวจรับ:** พิมพ์ BOQ 60 รายการ แบ่งหน้า A4 ถูกต้อง หัวตารางซ้ำทุกหน้า ไม่มีสีพื้นหลังติด; ไฟล์ xlsx เปิดใน Excel ไทยไม่เพี้ยน encoding

**ประมาณการ:** 3–5 วัน

### เฟส 4 — ประสิทธิภาพ + ความน่าเชื่อถือของข้อมูลราคา

**เป้าหมาย:** หน้าราคาเร็วแม้แคชเย็น และไม่ตายเมื่อ TPSO ล่ม (แก้ R1, R2)

- F4.1 **Snapshot ราคา** — เก็บผลลัพธ์ล่าสุดต่อ (จังหวัด, ปี) เป็นไฟล์ JSON ใน repo (`data/snapshots/`) ที่เติมโดย `scripts/make-snapshots.mjs` (dev + GitHub Actions) — serverless อ่านจากไฟล์ในบันเดิล (`outputFileTracingIncludes`) → first load < 2 วิ *(เปลี่ยนจากแผนเดิม "Vercel KV": ไม่เพิ่มบริการ/ค่าใช้จ่าย และไฟล์ต้อง commit ตรวจสอบย้อนหลังได้)*
- F4.2 **Fallback** — เมื่อ TPSO ล่ม ใช้ snapshot ล่าสุด + แสดง "ข้อมูล ณ วันที่ ..." ชัดเจน
- F4.3 **รีเฟรชตามกำหนด** — GitHub Actions รายวัน 04:00 (ไทย) ดึงราคาจังหวัดยอดนิยม + ปีงบปัจจุบัน แล้ว commit snapshot เข้า repo (Vercel cron ใช้ไม่ได้เพราะ serverless เขียนไฟล์ไม่ได้)
- F4.4 ย้ายที่เก็บโปรเจกต์เป็น **IndexedDB** (กันโควตา localStorage) + PWA (ใช้ offline ได้)

**เกณฑ์ตรวจรับ:** โหลด `/prices` เย็น < 3 วิ (ปัจจุบัน ~20–30 วิ); ปิดเน็ต TPSO ยังแสดง snapshot พร้อมป้ายอายุข้อมูล

**ประมาณการ:** 2–4 วัน

### เฟส 5 — บัญชีผู้ใช้ + ซิงก์ข้อมูล (ตามความพร้อม)

**เป้าหมาย:** ใช้ต่อเนื่องข้ามเครื่อง ไม่พึ่ง JSON manual (แก้ R5, R7)

- F5.1 Auth ด้วย **Supabase** (free tier): อีเมล/Google — ไม่เก็บรหัสผ่านเอง
- F5.2 ซิงก์โปรเจกต์ + คลังราคาส่วนตัว (RLS ต่อ user); โหมดไม่ล็อกอินยังใช้ localStorage ได้เหมือนเดิม
- F5.3 ลิงก์แชร์ BOQ **อ่านอย่างเดียว** (สำหรับส่งให้ผู้ตรวจสอบดูก่อนพิมพ์)
- F5.4 ปรับ `/privacy` ให้ครอบคลุมการเก็บข้อมูลบนคลาวด์

**เกณฑ์ตรวจรับ:** สร้าง BOQ บนเครื่อง A แก้ต่อบนเครื่อง B ได้; ผู้ไม่ล็อกอินไม่เห็นข้อมูลคนอื่น (ทดสอบ RLS ผ่าน)

**ประมาณการ:** 3–5 วัน · **ทำหลังเฟส 1–3 เสถียร** เพราะเพิ่มภาระดูแลข้อมูลส่วนบุคคล

### เฟส 6 — วิเคราะห์ราคาและดัชนี

**เป้าหมาย:** ยกระดับจาก "ตารางราคา" เป็น "เครื่องมือตัดสินใจ"

- F6.1 กราฟราคาย้อนหลังต่อรายการ (TPSO มีข้อมูลหลายปีใน `years[]`)
- F6.2 เปรียบเทียบราคาระหว่างจังหวัด (สำหรับงานหลายพื้นที่)
- F6.3 **ดัชนี Escalation factor (K)** จากดัชนีราคาวัสดุก่อสร้าง (CMI) ของ สนค. — ใช้ปรับราคาสัญญา
- F6.4 แจ้งเตือนเมื่อราคารายการที่ใช้ใน BOQ เปลี่ยน (ต้องมีเฟส 4 snapshot + เฟส 5 บัญชี)

**ประมาณการ:** 3–4 วัน

## 8. ภาคผนวก A — ข้อมูล API ของ สนค. (TPSO)

> สำรวจเมื่อ พ.ย. 2569 · แหล่งอ้างอิงหน้าเว็บ: https://index.tpso.go.th/construction-material-prices
> ⚠️ TPSO ไม่มี CORS header — เรียกได้จากฝั่งเซิร์ฟเวอร์เท่านั้น · ไม่ต้องใช้ API key

### A.1 `GET https://index.tpso.go.th/api/cmip/master`
ข้อมูลหมวดและจังหวัด (คงที่ ใช้แคชได้ยาว)
```json
{ "yearBase": [], "categories": [],
  "headCategories": [{ "code": "01", "name": "วัสดุเทหล่อกับที่" } /* …21 หมวด */],
  "types": [{ "type": "10", "typeName": "ส่วนกลาง" },
            { "type": "14", "typeName": "พระนครศรีอยุธยา" } /* …รายจังหวัด */] }
```

### A.2 `POST https://index.tpso.go.th/api/cmip/filter`
ดึงราคาตามเงื่อนไข (payload เต็มปี ~2MB, ส่วนกลาง 6,435 รายการ)
```json
{ "YearBase": 2558, "Categories": [], "Search": "",
  "Types": ["40"], "HeadCategories": ["01"], "TimeOption": true,
  "Period": { "StartYear": "2569", "StartMonth": "1", "EndYear": "2569", "EndMonth": "12" } }
```
Response (ตัดย่อ) — เดิน `children` แบบ recursive:
```json
[{ "unitName": "ลบ.ม.", "headCategory": "01", "headCategoryName": "วัสดุเทหล่อกับที่",
   "commodityCode": "0101010100100000",
   "commodityNameTH": "คอนกรีตผสมเสร็จ…",
   "years": [{ "year": 2569, "months": [
      { "priceCur": 2520.0, "priceVAT": null, "month": 10, "type": "14", "typeName": "พระนครศรีอยุธยา" }]}],
   "children": [] }]
```

### A.3 อื่น ๆ ที่พบ (ยังไม่ใช้)
- `POST /api/cmip/search` body `{ "Keyword": "…" }` — autocomplete ชื่อสินค้า
- `GET /api/csrf-token` — เว็บ สนค. เรียกก่อน POST แต่พบว่า filter เรียกตรงจากเซิร์ฟเวอร์ได้โดยไม่ต้องมี token (ควรกันไว้: ถ้าอนาคต 401 ให้เริ่มจากการหา token)

### A.4 ประกาศที่เกี่ยวข้อง (ตรวจสอบล่าสุดเสมอ)
สนค. ประกาศยกเลิกการเผยแพร่ราคาวัสดุก่อสร้าง**ส่วนกลาง**หลายช่วงเดือน
(กรกฎาคม 2567, พฤษภาคม 2568, ธันวาคม 2568, เมษายน 2569 เป็นต้น)
→ ระบบจึงออกแบบให้ใช้**ราคารายจังหวัด**เป็นหลัก และแสดงคำเตือนเมื่อเลือกส่วนกลาง

## 9. ภาคผนวก B — หลักการเดิมที่ต้องคงไว้

1. **ข้อมูลโครงการเป็นของผู้ใช้** — ไม่ส่งข้อมูลโครงการขึ้นเซิร์ฟเวอร์ นอกจากผู้ใช้เปิดใช้ซิงก์เอง (เฟส 5)
2. **ความโปร่งในที่มาราคา** — ทุกราคาที่แสดงต้องระบุแหล่งที่มา (สนค./ราคาส่วนตัว) และเดือนอ้างอิง
3. **Disclaimer ไม่ถูกลบ** — ราคา สนค. ไม่ใช่ราคามาตรฐานกรมบัญชีกลาง ต้องมีคำเตือนทุกจุดที่แสดงราคา
4. **ธีมดาร์คแก้ที่จุดเดียว** — สี override รวมที่ `app/globals.css` + print ขาวดำ; ห้าม hardcode สีใหม่ข้ามไฟล์โดยไม่ผ่านตัวแปร
5. **Deploy ผ่าน git เท่านั้น** — push `main` แล้ว Vercel build เอง; ไม่แก้ไฟล์บน Vercel dashboard
6. **ไฟล์ PowerShell ใน workflow ต้อง ASCII** — ข้อความ commit ฯลฯ เขียนภาษาอังกฤษกันปัญหา encoding
