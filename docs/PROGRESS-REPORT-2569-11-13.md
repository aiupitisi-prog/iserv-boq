### 3.2 วิธีสกัด (`scripts/parse-w480.mjs`)

- **geometry จาก mupdf** ไม่ใช่ text flow: คอลัมน์จาก x0 (no <68 · name <300 · unit <340 · price <385 · note ≥385), แถว = กลุ่ม y ±4, state ต่อเนื่องข้ามหน้า
- **normalizer สระ 2 ขั้น**: collapse whitespace → `ำ→า` → `" า"→ำ` (ครอบทั้ง 3 ฟอนต์; ตรวจแล้วไม่มี "จานวน/กาหนด" แบบไม่มี space)
- **ข้อยกเว้นที่ตรวจจากตัวประกาศจริง:**
  - พิมพ์ลำดับ `2.68` (ควรเป็น 2.6.8) → เก็บ `noPrinted` + `anomaly` ไม่แก้ต้นฉบับ
  - ชื่อรายการตัดบรรทัด (วงเล็บ เช่น `(เสาเข็ม คอร. รูปกลมกลวง)`) → รวมกลับเป็นชื่อ entry
  - bullet เชิงหมายเหตุ (`- ไม่รวมงาน...`) และ variant ที่ไม่มีราคาทั้ง subtree → ย้ายเป็น `notes`
- **fail loudly:** ราคาไม่ใช่บาทเต็ม · ลำดับซ้ำ/กระโดด (รายพ่อแม่) · บรรทัดตารางหลุดขอบ · จำนวนหน้าไม่ตรง · **sha256 ของ PDF ไม่ตรงที่ pin** → throw พร้อมหน้า+y
- **`--dry` / `--strict`**: `--strict` ล้มเหลวเมื่อมี issues; ไฟล์ generated บันทึก `notes`/`issues` ไว้ในหัวไฟล์ (`W480_2569_QUALITY = { notes: 89, issues: 0 }`)

### 3.3 โครงสร้างที่เพิ่มใน `lib/ruleset.ts`

- `WagePriceRow` / `WageVariant` / `WageEntry` / `WageSchedule` · `Ruleset.wageSchedule?` · `Ruleset.wageScheduleChecksum?` · `Ruleset.provenance?`
- `rulesetChecksum` ใส่ `wageSchedule` **เฉพาะเมื่อมี entries** → ชุดกฎเดิม checksum ไม่เปลี่ยน (backward compatible)
- `getW480Ruleset()`: `labor` จากหมายเหตุข้อ 1 · `provenance = mirror-unverified` · schedule ถูก freeze ลึกกัน mutate
- `verifyW480Checksums()`: ตรวจรายรายการ + ชุด + **ruleset checksum** + checksum ของรายการที่ไม่มีอยู่

### 3.4 Import/export (`lib/ruleset-import.ts`)

- ตรวจโครงสร้างเข้มเท่า parser: `no` รูป `1.2.3` ไม่ซ้ำ · `level` ตรงกับจำนวนช่วง · ราคาเป็นบาทเต็ม **> 0** · ฟิลด์ข้อความถูกชนิด · `notices` เป็น string
- `wageScheduleChecksum` pattern เดียวกับ `setChecksum` (ไฟล์ถูกตัด/แก้ภายหลัง = ปฏิเสธ)
- `entries` ว่าง = ถือว่าไม่ระบุ (ตรงกับ comment เดิม)
- `provenance` ผ่าน round-trip (ไม่รวมใน checksum)

### 12.2 แก่นสาระ — ผ่อนผัน ๓ กรณี

หนังสือแก้ความเข้าใจเรื่องช่วงเวลาเปลี่ยนตาราง (window ๙ มิ.ย. ๒๕๖๙ จนถึงวันที่ ว 475 มีผลใช้บังคับ):

1. **ข้อ ๑ (เงื่อนไขเปิด):** คำนวณราคากลางด้วยตารางค่าดำเนินการและค่าเสื่อมราคา**ใหม่** (ตามที่อ้างถึง ๑) ใน window และหัวหน้าหน่วยงานให้ความเห็นชอบราคากลางแล้ว → "ให้ดำเนินการดังนี้" (๒ กรณีย่อย)
   - **๑.๑** ยังไม่ประกาศเผยแพร่ร่างขอบเขตของงาน/รายละเอียดของพัสดุ และร่างเอกสารเชิญชวนเพื่อรับฟังความคิดเห็น (หรือยังไม่ประกาศสอบราคา/ประกวดราคา/โดยวิธีคัดเลือก/หนังสือเชิญชวนแบบเฉพาะเจาะจง) → มอบหมายคณะกรรมการ…พิจารณา(ทบทวน)**ราคากลางใหม่** — tail ข้อความถอดไม่เต็ม (ป้าย unverified)
   - **๑.๒** ดำเนินการล่วงเลยไปแล้ว และหัวหน้าหน่วยงานเห็นว่าราคากลางนั้นใช้เปรียบเทียบราคาที่ผู้ยื่น(เสนอ)ด้วยจริง → ให้ดำเนินการตามข้อนั้น(?)ต่อไป — คำเชื่อมกลางถอดไม่เต็ม (ป้าย unverified)
2. **ข้อ ๒ (ตารางเก่า):** คำนวณใน window เดียวกันแต่ด้วยตารางของ**หลักเกณฑ์ฉบับ 2560** (ประกาศลงวันที่ **๑๙ ตุลาคม ๒๕๖๐** — อ่านชัดจากสแกน) → **"ให้ถือว่าเป็นการปฏิบัติตาม(ที่?)อ้างถึง ๑"** — ไม่ต้องคำนวณใหม่ (วันที่เปิด window กำกวม รับ "๙ มิถุนายน ๒๕๖๙" ตามบริบท + kb — ป้าย unverified ที่ตัวเลขเปิด)

ไม่มีตารางราคา/อัตราใด ๆ ในเอกสารนี้ → **ไม่สร้าง ruleset** — ใช้เป็นหลักฐานกำกับเงื่อนไขผ่อนผันของชุด 2569 เท่านั้น (เมื่อเครื่องยนต์ตรวจ window เปลี่ยนตาราง ต้องอ้างข้อ ๑/๒ นี้)

## 13. รอบ 7 (ต่อวันเดียวกัน) — สูตรคิดค่าเครื่องจักร ว 475 + เครื่องคิดบนหน้า /rulesets

### 13.1 สูตรในเครื่องยนต์ (`lib/calc/machinery.ts`)

`machineryCost(schedule, query)` — pure function (ไม่มี I/O) รับ: ลำดับ + ชื่อบรรทัด (+ occurrence) · ราคาน้ำมันดีเซล (สตางค์/ลิตร) · สภาพงาน (ปกติ/ฝนชุก) · ปริมาณ (ไม่บังคับ)

| กฎที่บังคับ | ผลเมื่อผิด |
|---|---|
| ไม่พบรายการในตาราง | `ITEM_NOT_FOUND` |
| บรรทัดหัวข้อที่ต้นฉบับไม่พิมพ์ราคา (`priced = none`) | `ITEM_NO_PRICE` (ไม่ถือเป็น 0) |
| ราคาน้ำมันนอกช่วงตาราง หรือ NaN/Infinity | `FUEL_OUT_OF_RANGE` — **ไม่ extrapolate** |
| ช่องราคาว่าง หรือ `ค่าดำเนินการ + ค่าเสื่อมราคา ≠ รวมค่างาน` | `DATA_INCONSISTENT` (ข้อมูลเพี้ยน → ให้นำเข้าใหม่) |
| ปริมาณ ≤ 0 / ไม่ใช่ตัวเลข / ทศนิยมเกิน 4 ตำแหน่ง | `BAD_QUANTITY` |
| ปริมาณที่ทำให้ยอดรวมเกิน `Number.MAX_SAFE_INTEGER` | `BAD_QUANTITY` (ไม่คืนยอดที่เพี้ยน) |
| ค่าก้อนเดียว (`lump`) ปริมาณไม่ใช่จำนวนเต็ม ≥ 1 | `BAD_QUANTITY` (คิดเป็นครั้ง) |

- ผลลัพธ์: `perUnitSatang` (ห้าค่า = รวมค่างานตามคอลัมน์ปกติ/ฝนชุก · ก้อนเดียว = ค่าต่อครั้ง) · `amountSatang` (null เมื่อไม่ระบุปริมาณ) · `notes` (ที่มา/การปัดเศษ) · `unit`
- เงินเป็น **สตางค์ integer** ตลอด — คูณแบบ integer scaling (ปริมาณ ×10000) แล้วปัด half-up เป็นสตางค์ **ครั้งเดียว** · ไม่แก้ข้อมูลต้นฉบับ (มีเทสต์)
- `notes` ระบุ **หัวตารางที่พิมพ์ + หน้าต้นฉบับ (`sourcePages`)** และ `rulesetId/checksum` เมื่อผู้เรียกส่ง `provenance` · ระบุว่าวิธีปัดเศษ **ยังไม่ยืนยันกับต้นฉบับ** (ข้อสมมติ 2 ของ PRD) · ยอดที่ปัดลงเป็น 0.00 มีหมายเหตุว่าเป็นผลของการปัดเศษ
- ทุกผลลัพธ์ระบุว่าเป็น **"ต้นทุนค่าเครื่องจักร" ยังไม่รวม Factor F/กำไร/VAT**

### 13.2 UI (`app/rulesets/`)
